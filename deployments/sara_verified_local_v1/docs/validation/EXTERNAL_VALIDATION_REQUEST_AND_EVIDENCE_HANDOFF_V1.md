# Worldshepherd External Validation Request + Evidence Handoff v1

**Document class:** laboratory engagement / evidence-custody specification  
**Applies to:** WS-AlTi and Adaptive Metasurface first-wave campaigns  
**Status:** ready for facility scoping; no facility engagement is implied by this document.

## 1. Purpose

Worldshepherd is seeking **measurement and characterization**, not a laboratory endorsement of a product claim. The requested output must allow an independent reviewer to reconstruct what article was tested, how it was measured, which calibration/method controls applied, and which files support every reported result.

A polished report without the underlying machine-readable/raw evidence is not sufficient for PVK scientific-maturity advancement.

## 2. Common facility response requested before work begins

Please provide:

1. whether the requested specimen/article can be accepted by the facility;
2. applicable test/characterization methods and current procedure/standard revisions;
3. sample geometry, preparation, packaging, electrical-interface, or fixture requirements;
4. instrument capability/range and practical detection/measurement limits;
5. calibration approach and whether calibration records can accompany the deliverable;
6. expected raw and processed data formats;
7. whether measurement uncertainty can be reported for the requested observables;
8. estimated price/rate structure and turnaround;
9. external-user agreement, NDA/IP/confidentiality, publication, and data-retention terms;
10. whether Worldshepherd personnel may provide a **preregistered sample map and analysis plan** without requiring disclosure of protected formulation details beyond what is needed to perform the test;
11. whether the laboratory can return unused/destructively tested specimen remnants with final custody status documented;
12. any safety/SDS/export-control or material-disclosure requirements before acceptance.

## 3. Required evidence deliverable format

For each campaign, request the following where applicable:

### 3.1 Facility and instrument identity

- laboratory organization and facility;
- test dates/times and time reference;
- instrument type, manufacturer/model, serial or asset identifier where releasable;
- firmware/software version where relevant;
- calibration record/certificate/reference ID;
- calibration valid-at-test state;
- fixture/reference-plane/range configuration.

### 3.2 Article/sample identity

- Worldshepherd sample/article ID preserved throughout testing;
- parent build/lot ID supplied by Worldshepherd;
- specimen type;
- orientation and/or measurement coordinates where relevant;
- received condition and any preparation performed by the lab;
- custody receipt and disposition.

### 3.3 Methods

- laboratory procedure ID;
- external standard/method reference and revision where applicable;
- deviations from the stated method;
- environmental conditions material to the result;
- analysis/processing settings that materially alter reported values.

### 3.4 Raw evidence

Return the **native raw files** generated by the instrument whenever the facility is permitted to do so, plus an interoperable export where practical.

Examples:

- spectroscopy/spectral data;
- microscopy images with acquisition metadata;
- EBSD/XRD/XRF/EDS/EPMA datasets;
- tensile machine force/displacement/strain/time data;
- hardness map coordinates and individual readings;
- VNA Touchstone or equivalent complex S-parameter data;
- antenna/range angle-amplitude-phase data;
- environmental/temperature logs;
- command-state/event timing where the test article is actively controlled.

Do not substitute screenshots for raw numerical files.

### 3.5 Processed results

Each reported result should identify:

- sample ID;
- observable;
- value and unit;
- uncertainty or stated limitation;
- method ID;
- raw source file(s);
- exclusions/rejected readings and reasons;
- processing/analysis software and revision where material.

### 3.6 Calibration and reference evidence

Where releasable, include:

- calibration certificate/record or facility reference ID;
- reference-standard/material identity;
- blank/background/reference measurements;
- pre/post verification where the method uses them.

If calibration artifacts cannot be released, provide enough facility-controlled reference information for Worldshepherd to document that a valid calibration existed at the time of acquisition.

## 4. Worldshepherd file-custody requirement

Upon receipt, Worldshepherd will:

1. preserve the original lab package unchanged;
2. compute SHA-256 for each file;
3. assign the package a canonical PVK digest;
4. store laboratory identity, campaign ID, sample IDs, method IDs, instrument/calibration references, acquisition time, and chain-of-custody events;
5. keep processed/reanalyzed outputs separate from immutable raw files;
6. record all later exclusions and analysis revisions instead of overwriting history.

The laboratory is not required to use Worldshepherd software.

## 5. Independence classification

Worldshepherd distinguishes:

- **external non-independent:** outside measurements exist, but financial, design, analysis, shared-personnel, or other dependencies mean the result is not treated as independent replication;
- **external independence pending:** outside evidence was acquired, but conflict/contract/test-design independence has not yet been reviewed;
- **external independent reviewed:** the external result and relationship have passed Worldshepherd independence review.

A laboratory being external does **not automatically** make a test independent replication.

## 6. WS-AlTi request module — `SV-WSALTI-001-P1`

### Objective

Determine whether preregistered candidate/baseline states are analytically distinguishable above measurement uncertainty and whether a repeatable composition–microstructure–property relationship exists across independently manufactured builds.

### Initial requested capability set

Facilities may quote all or a subset, but should clearly identify which measurements are in scope:

- bulk/local composition appropriate to the target elements and concentration range;
- mapped local chemistry across declared zones;
- optical/SEM microstructure;
- EDS/WDS/EPMA or other appropriate local-composition method;
- EBSD and/or XRD where it answers the frozen microstructure/phase question;
- porosity/defect characterization appropriate to the coupon;
- microhardness mapping;
- tensile testing to the applicable current metallic-material method;
- sample preparation needed for the selected measurements.

### Worldshepherd will provide before testing

- specimen IDs and build IDs;
- coordinate/extraction map;
- declared baseline/candidate grouping encoded if blinding is practical;
- required measurement locations;
- primary/secondary endpoints;
- protected-material disclosures actually required for safe/valid testing;
- applicable SDS/shipping information.

### Do not infer from this request

The campaign does not ask the laboratory to certify:

- aerospace qualification;
- fatigue/corrosion performance not explicitly tested;
- a particular commercial valuation;
- “programmability” from a single spatial gradient;
- superiority over incumbent alloys unless the comparison is explicitly designed, preregistered, and measured.

## 7. Adaptive Metasurface request module — `SV-META-001-P1`

### Objective

Determine whether a bounded single-band Worldshepherd article produces repeatable command-dependent complex electromagnetic response and, at array level, the preregistered beam/null behavior predicted by the frozen model.

### Initial requested capability set

- calibrated VNA or equivalent complex reflection/transmission measurement over the declared band;
- appropriate fixture/reference-plane calibration;
- raw complex `S11` and `S21` where applicable;
- repeat command-state cycles with temperature recorded;
- reference/control article measurement;
- power-cycle repeat;
- radiation/scattering pattern measurement for an array article when facility geometry supports it;
- beam-peak/null angle and level from the raw angular dataset;
- polarization/background/reference measurements appropriate to the test;
- source power and relevant acquisition settings.

### Worldshepherd will provide before testing

- declared operating band inside facility capability;
- article/geometry revision;
- command interface and safe operating envelope;
- State A / State B preregistered command sequence;
- predicted phase/amplitude state ordering;
- predicted beam or null region;
- thermal/power limits;
- fixture/interface drawings needed by the laboratory.

### Do not infer from this request

A measured beam or null result is not, by itself:

- “stealth”;
- “cloaking”;
- broadband cancellation;
- optical-spectrum validation;
- aerospace environmental qualification.

Those require later application-specific campaigns.

## 8. Acceptance checklist on receipt

A laboratory package is **structurally reviewable** only if Worldshepherd can answer YES to the applicable items:

- [ ] sample/article identity preserved;
- [ ] custody events preserved;
- [ ] acquisition times and time reference supplied;
- [ ] measurement method identified;
- [ ] instruments identified sufficiently for audit;
- [ ] calibration references exist;
- [ ] valid-at-test calibration state known;
- [ ] raw numerical/native data returned;
- [ ] result-to-source-file traceability exists;
- [ ] uncertainty/limitations reported or explicitly stated unavailable;
- [ ] exclusions/deviations are disclosed;
- [ ] package/file SHA-256 values can be generated and verified;
- [ ] laboratory relationship/independence classification recorded.

Passing this checklist **does not mean the hypothesis passed**. It only means the evidence is complete enough to review scientifically.

## 9. PVK ingestion

The controlled SARA branch implements `ws-lab-evidence-package-1` and an admin-only validation route:

`POST /admin/physics/lab-packages/validate`

The endpoint validates referential integrity, raw-data presence, calibration references/state, and evidence-package structure; returns a canonical SHA-256 digest and blockers/warnings; writes an audit event; and always returns `maturity_promoted=false`.

Actual promotion remains a separate PVK review/replication/approval decision.
