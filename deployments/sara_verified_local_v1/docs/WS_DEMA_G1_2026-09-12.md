# WS-DEMA G1 — Directed-Energy Mission Assurance Demonstrator

**Date:** 2026-09-12  
**Status:** INTERNAL REPRODUCIBLE SOFTWARE TARGET  
**Claims ceiling:** non-weapon synthetic mission-assurance integration only

## Purpose

WS-DEMA G1 composes existing Worldshepherd/SARA primitives into a bounded mission-assurance demonstrator for high-power, sensor-rich systems. The G1 artifact does **not** implement target selection, aimpoint optimization, beam steering, atmospheric compensation, fire control, lethality estimation, autonomous engagement, or emitter control.

The purpose of G1 is to show that Worldshepherd can accept benign subsystem-health telemetry, classify degraded state, preserve configuration lineage, require identified-human approval before a configuration transition, generate ECHO-compatible evidence records, support deterministic replay, and perform an append-only rollback drill.

## Safe telemetry boundary

The initial fixture uses only synthetic mission-assurance metrics:

- available electrical power;
- cooling-loop outlet temperature;
- network latency;
- configuration version/state;
- maintenance-policy state.

Future G1 additions may include benign alignment-health proxies, vibration, ambient environment, software provenance, SBOM state, and maintenance countdowns. They must remain non-targeting and non-lethality-oriented.

`ws_dema.py` recursively rejects configuration fields whose semantics would move the G1 demo into a weapon-control role, including target identifiers, aimpoints, fire commands, engagement commands, kill-probability fields, beam commands/steering, or weapon release.

## G1 flow

1. Parse `WS-DEMA-G1-V1` scenario and validate the non-weapon boundary.
2. Evaluate synthetic telemetry against declared expected envelopes.
3. Create an append-only baseline configuration snapshot.
4. Create a configuration-change proposal in `PROPOSED` state requiring `identified-human-authority`.
5. Keep the baseline active unless an identified reviewer explicitly approves the candidate.
6. Generate a readiness state (`READY` or `DEGRADED`) from observed subsystem-health deviations.
7. Emit ordered replay events for health findings and authorization state.
8. Emit ECHO-compatible audit records with stable IDs and `AT_LEAST_ONCE` delivery semantics.
9. When an approved configuration must be reverted, append a rollback snapshot that reproduces the baseline payload while preserving lineage.

## Synthetic demonstration fixture

`fixtures/ws_dema_synthetic_v1.json` intentionally places `coolant_outlet_c` above its expected envelope while power and network state remain nominal. Expected outcome:

- readiness = `DEGRADED`;
- degraded metric = `coolant_outlet_c`;
- without human approval, active configuration remains the baseline;
- with explicit approval, candidate configuration becomes the custody head;
- rollback produces a new append-only snapshot with the baseline payload;
- ECHO accepts the generated audit records and deduplicates an exact replay of the same stable event.
