## Current security evidence beyond the historical report

### Authorization

`worldshepherd_sara/auth.py` currently:

- requires independently configured relay and admin secrets;
- requires each secret to contain at least 24 characters;
- rejects identical relay/admin tokens;
- uses `hmac.compare_digest` for token comparison;
- returns 401 for missing/malformed/invalid bearer credentials;
- returns 403 when an authenticated non-admin attempts an admin route.

### API enforcement

`tests/test_api.py` directly verifies:

- every current admin endpoint rejects relay credentials;
- invalid relay credentials are rejected;
- both authenticated roles can record a local-only relay;
- admin registry PATCH/GET succeeds;
- admin self-test checks persistent storage, registry read, and audit append;
- admin audit access succeeds and includes a registry-patched event;
- malformed, oversized, over-nested, and over-sized structured inputs do not mutate protected state;
- registry/audit symlink swaps fail closed;
- runtime data/registry/audit file modes are restricted.

### Storage / custody

`worldshepherd_sara/storage.py` currently uses:

- data directory mode `0700`;
- registry/audit file mode `0600`;
- `O_NOFOLLOW` where supported for protected file opens;
- atomic registry replacement;
- file and directory `fsync` for durability;
- bounded audit-tail reads and explicit corruption labels.

### Secret handling / deployment evidence

- `.env` is excluded by both `.gitignore` and `.dockerignore`.
- `scripts/verify_deployment.sh` renders Compose evidence only after replacing both token values with `<REDACTED>` and fails if exactly one occurrence of each token field is not found.
- the same deployment verifier executes `admin_smoke_test.sh` before restart and again after restart.
