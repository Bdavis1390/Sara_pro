## Preserved evidence

`bridge-evidence.json` is the extracted payload from the successful `qcrypto-echo-deployed-bridge-evidence` artifact generated by workflow run `34873323676` on the validated implementation anchor.

`publication-readiness.json` is the extracted payload from the successful `qcrypto-white-page-publication-readiness` artifact generated by workflow run `34921523881` on the publication revision.

The original artifact ZIP digests and the extracted payload SHA-256 values are recorded in `manifest.json`.

## Verification model

The preservation gate verifies:

1. the two anchored commits exist in repository history;
2. each commit points to the recorded Git tree;
3. the white-page Git blob exists;
4. each preserved evidence payload hashes to the value recorded in the manifest;
5. the bridge payload reports its bounded PASS state and expected reconciliation behavior;
6. the publication payload reports `posting_status: GO` and references the validated implementation anchor;
7. claims-control exclusions remain false.

This is a repository-level proof-of-work and provenance record. It is not an external notarization and does not transform unsigned commits into signed commits.

## Remaining independent-custody tier

For stronger authorship/time custody, preserve a portable archive of this directory together with the original artifact ZIPs, compute one final SHA-256 for the archive, and then place that digest in at least one independent timestamp/notary system and one independently controlled storage location. A signing-capable release/tag should be added when that capability is available.

## Claims boundary

The bundle establishes only the internally validated software behavior recorded by the referenced evidence. It does not establish production deployment, migration execution, transaction signing, movement of value, post-quantum security of the Ed25519 checkpoint, Federal compliance, WS-CAE conformance, third-party validation, or physical-system qualification.
